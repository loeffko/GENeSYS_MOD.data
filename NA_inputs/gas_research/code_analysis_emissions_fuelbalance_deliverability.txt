--- power_only_mechanism:
POWER-ONLY (switch_power_only_mode=1, test/test_northamerica.jl:31-32): the set filter (Conversion Script/Set_filter_file_NorthAmerica.xlsx, Fuel_selection = Power + 6 Power_* only) strips Gas_Natural, so the loaded workbook has no IAR rows for any P_Gas_* tech, an EMPTY Par_EmissionContentPerFuel sheet (header only), no R_/Z_ techs, and Sets.Fuel = [Power, Power_General, ...] (read from the 'Sets' sheet col D in read_sets, dataload.jl:173). Consequently Maps.Tech_Fuel[P_Gas_CCGT] = ["Power"] and E1's first term is identically 0. Emissions and fuel cost are instead injected by power_only_precompute!(Params, Sets, Switch) (src/genesysmod_precompute_powerOnly.jl:38-190), called right after dataload in genesysmod_main.jl:114, genesysmod_dispatch.jl:106 and genesysmod_dispatch_fullyear.jl:398. It reads the allFuels workbook (RegularParameters_NorthAmerica_allFuels.xlsx, which still has Gas_Natural, R_Gas, Z_Import_Gas, the ECPF rows) - sheets IAR/OAR/VariableCost/ECPF (lines 50-53). For every allFuels IAR group (r,t,m,y) with t in the power-only Sets.Technology (line 138-139): (a) modes using a SKIP fuel (Gas_Synth) get their Power OAR zeroed (144-150); (b) fuel_cost_pa = sum_f IAR*upstream_vc(r,f,y) where upstream_vc looks up VariableCost of 'Z_Import_'*alias(f) (FUEL_ALIAS Gas_Natural->Gas, LBG/LSG->LNG, H2_Blend->H2, lines 105-122) or UPSTREAM_TECH (Gas_Bio->R_Biogas w/ emission 0, Nuclear->R_Nuclear, 96-101), and Params.VariableCost[r,t,m,y] += fuel_cost_pa (163-170); (c) for each e: emission_pa = sum_f IAR*ECPF[alias(f),e] and Params.OutputEmissionRatio[r,t,e,m,y] = emission_pa / OAR_Power (173-182). Nothing needs undoing elsewhere: VariableCost is an '+=' on the plant's own O&M value; OutputEmissionRatio is zero-initialised (dataload.jl:416); the E1 power-only term then evaluates to 0 for those modes. It is the only option that is data-driven, region/use-case agnostic, active in the current power-only NA phase AND unchanged in the full-sector phase, and that models the physics as a shared pool with a proper shadow price. Key finding driving the choice: the user's proposed Par_FuelDeliverabilityLimit[Region, Fuel, Year] cannot work in phase 1 because (i) the NA power-only workbook has no Gas_Natural fuel and gas plants carry no InputActivityRatio (thermal plants are fuel-less by design; Set_filter_file_NorthAmerica.xlsx Fuel_selection = Power + Power_* only), so RateOfUse of gas is identically 0, and (ii) any CSV column named Fuel is filtered against Fuel_selection by the converter (process_parameters.py:145-147), so Gas_Natural rows would be dropped from the Excel before the model sees them. --- time_independent_analysis:
How the tag is built (src/genesysmod_equ.jl:252-259): TagTimeIndependentFuel[y,f,r] = CanFuelBeUsedOrDemanded * (1 - CanFuelBeProduced), then any fuel with Par_TagTimeIndependentFuel[f]==1 is forced to 1 for all (y,r). CanFuelBeUsedOrDemanded (equ.jl:181-192) is 1 if some tech consumes the fuel with positive TotalAnnualMaxCapacity*CF*AF*ModelPeriodLimit*AnnualLimit OR SpecifiedAnnualDemand>0; CanFuelBeProduced (equ.jl:227-237) is 1 if some tech outputs it with the same positive-capacity product. Two regimes:

(a) Tag == 0 -> EB2_EnergyBalanceEachTS (equ.jl:428-436, GAMS genesysmod_equ.gms:243-244): for every y,l,f,r an EQUALITY  sum_out(RateOfActivity*OAR)*YearSplit == Demand[y,l,f,r] + sum_in(RateOfActivity*IAR*TimeDepEfficiency)*YearSplit + NetTrade[y,l,f,r]. Demand[y,l] = SpecifiedAnnualDemand * SpecifiedDemandProfile / YearSplit * YearSplit (dataload.jl:889-892). The dual is pushed to considered_duals -> an hourly regional gas price comes out of the run. Trade enters per timeslice via EB4 (equ.jl:419-422) and Import/Export vars per (f,r,rr,l).

(b) Tag != 0 -> EB3_EnergyBalanceEachYear (equ.jl:463-467, gms:246-247): one INEQUALITY per y,f,r: annual production >= annual use + NetTradeAnnual. Note: EB3 contains NO Demand / SpecifiedAnnualDemand term at all (both Julia and GAMS) - an exogenous non-power gas demand on a time-independent fuel is silently dropped from the balance (it still influences CanFuelBeUsedOrDemanded, SC3 phase-in scaling and errorcheck #8/#11, but nothing has to supply it). It is also '>=' (free disposal), so surplus extraction is unconstrained.

Current state for Gas_Natural: there is no Par_TagTimeIndependentFuel row (docs parameters.rst:589-593 describe it as 'commodities where no flow or trade restrictions are assumed, e.g. Lignite, HardCoal'). With R_Gas / Z_Import_Gas selected and their capacity-product positive in a region, CanFuelBeProduced=1 -> derived tag 0 -> timeslice balance. Pitfall: in any region where BOTH producers are dead (e.g. Z_Import_Gas AvailabilityFactor missing = 0, R_Gas ModelPeriodActivityMaxLimit zeroed by bounds.jl:43-47) and no trade route exists, the derived tag flips to 1 there and EB3 reads 0 >= use + NetTradeAnnual -> gas plants in that region are forced to zero activity (no infeasibility tech exists for Gas_Natural: update_inftechs_params! dataload.jl:307-310 only creates Infeasibility_<end_use> for Power/HeatFuels/TransportFuels).

Recommendation for an infrastructure model: keep Gas_Natural timeslice-resolved (no tag row). Consequences: (1) LP size: +|R| x |L| x |Y| equalities (10 x 8760 x 16 = 1.4M rows at nthhour=1) plus Import/Export vars per routed pair and hour, plus D_Gas_Methane RateOfActivity and storage-level rows per hour; (2) the exogenous demand profile actually binds hour by hour (needs a gas-shaped TS, otherwise it is the electric LOAD shape); (3) R_Gas / Z_Import_Gas have AF=CF=1 and no ramping, so extraction/imports can swing freely per hour - the only things that make the hourly gas balance meaningful are per-timeslice pipeline caps (TrPA1a, disabled), the flat-import rule TrPA2b (disabled: Z_Import_Gas[l] <= 1.05 x annual share), storage E2P (S7a/b) and the demand shape; (4) gas storage S_Gas_Methane only has a role under (a) - under (b) it is pointless. Tagging it time-independent instead gives one annual '>=' per region: cheap, no storage/pipeline timing, trade capped only annually (and only if TrC7 is re-enabled), and the non-power demand must be modelled some other way (e.g. as a dedicated consuming technology) because EB3 ignores Demand.
